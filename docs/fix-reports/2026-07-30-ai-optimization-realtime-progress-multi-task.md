# AI 优化实时进度与多任务展示改造复盘

- 日期：2026-07-30
- 模块：博客 / AI 优化 / 后台任务中心
- 分类：AI Assist 修复复盘
- 状态：已部署现网

## 问题现象

AI 优化提交后会跳离文章编辑页，用户只能进入任务列表查看一个缺少上下文的百分比。任务虽写入了多个阶段，但 Worker 在一个长事务中直到结束才提交，因此 SSE 无法在模型调用期间实时收到中间进度。多个任务并行时，列表也不能直观看出对应文章、使用的 AI 和各自阶段。

## 根因

1. 优化任务的 10%、35%、55%、80%、100% 状态处于同一数据库事务，实际在任务结束时一次性可见。
2. 创建任务的 REST 响应没有立即写入前端任务 Store，要等待 SSE 或再次拉取。
3. AsyncJob 缺少用于展示的文章标题、AI Provider、优化类型等上下文。
4. 编辑器提交成功后强制跳转，无法一边继续编辑一边观察任务。
5. REST 刷新可能覆盖已经由 SSE 更新的新状态，存在进度回退风险。

## 改造内容

### 后端实时进度

- 优化任务创建时即进入 `queued / 等待执行`。
- 在任务结果中保存不可变展示上下文：文章 ID、标题、Provider、优化类型和范围。
- Worker 将各阶段作为独立短事务提交，SSE 可实时消费：

  - 0%：等待执行
  - 10%：正在准备文章
  - 35%：正在分析内容
  - 55%：Radio 或 AI Assist 正在生成优化内容
  - 75%：已收到结果，正在检查
  - 85%：正在校验格式与受保护内容
  - 95%：正在保存优化候选
  - 100%：待审核

- 保存最终候选结果时继续保留任务展示上下文。

### 前端展示

- 提交成功后留在文章编辑页，不再强制跳转。
- 新任务立即写入 Pinia Store，消除等待 SSE 首帧的空档。
- 编辑页新增文章级优化任务区，可同时展示多个任务的：

  - 使用的 AI
  - 当前状态和阶段
  - 实时百分比及进度条
  - 已用时间
  - 失败原因
  - 任务详情入口

- “AI 优化”按钮在运行期间显示 `优化中（N）`。
- 全局任务中心增加并行数量、文章标题和 Provider。
- AI 任务页增加进行中、待审核、总任务统计，并改为上下文完整的任务卡片。
- REST 列表只作为基线补全，不再覆盖版本更新更高的 SSE 状态。

- 后端 PostgreSQL 优化流水线集成测试：8 项通过。

测试覆盖了任务上下文、Provider 显示、多任务并列、SSE 版本去重、候选结果上下文保留和完整阶段事件。

### 现网验证

在现网同时提交两个 Radio 优化任务：

- 两个任务均立即返回 `queued / 等待执行`。
- 任务能够分别进入 `processing / Radio 正在生成优化内容`。
- 两个任务均到达 `waiting_user / 待审核`。
- 持久事件包含 0、10、35、55、75、85、95、100 全部进度点。
- 临时文章已清理，测试任务已取消。

### 部署健康

Backend、Frontend、Nginx、PostgreSQL、Redis、RabbitMQ、Outbox Publisher、Celery Beat、Fast Worker、Heavy Worker 均健康；Fast/Heavy Worker ping 正常。

## 回滚方式

1. 回滚前端的文章进度组件、任务列表及任务 Store 修改。
2. 回滚后端任务上下文和 Worker 阶段提交修改。
3. 重新执行 `./deploy/scripts/deploy.sh up`。

本次不包含数据库结构变更，无需执行数据库 downgrade。已生成的任务上下文位于 JSON 结果内，旧代码会安全忽略。
