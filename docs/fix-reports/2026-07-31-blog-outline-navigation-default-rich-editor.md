# 修复复盘：文章大纲章节定位与默认富文本模式（2026-07-31）

- 日期：2026-07-31
- 模块：博客 / 文章编辑器 / 大纲
- 分类：AI Assist 修复复盘
- 状态：已部署现网

## 问题现象

1. 文章编辑页能够根据 Markdown 标题生成大纲，但大纲项只是静态文本，点击后不会跳转到正文对应章节。
2. 文章打开时没有可靠地进入编辑模式：后端历史值为 `markdown`，前端模式名为 `source`，两边名称没有转换。
3. 用户切换到源码模式时，前端会把后端不接受的 `source` 直接提交，可能产生 HTTP 422。

## 根因

- 大纲 `<li>` 没有点击事件，也没有保存标题在正文中的行号、字符位置和渲染顺序。
- 源码、富文本、预览和分栏四种视图没有统一的章节定位接口。
- 数据库允许的编辑模式为 `markdown | rich | split`，而前端使用 `source | rich | split | preview`；加载和保存时均缺少显式映射。
- 历史数据默认值为 `markdown`，因此无法满足文章默认以富文本打开的要求。

## 修复内容

### 大纲导航

- 大纲项改为可聚焦、可键盘操作的按钮，并增加当前选中状态。
- 解析标题时保存标题层级、文本、Markdown 行号、字符偏移和渲染索引。
- 忽略围栏代码块中的伪标题，避免大纲和正文标题错位。
- 源码模式点击后移动光标并滚动到标题行。
- 富文本模式点击后定位 Milkdown 实际渲染的标题节点，并平滑滚动到可视区域。
- 预览模式通过 `data-outline-index` 定位对应标题。
- 分栏模式同时定位源码和预览。
- 目标章节和大纲按钮提供短暂视觉反馈。

### 默认富文本与模式兼容

- 新文章的 ORM、服务层和数据库默认值统一为 `rich`。
- 数据迁移 `0015_default_rich_editor_mode` 将现有 `markdown` 默认值一次性迁移为 `rich`，保留原有 `split` 数据。
- 新增前后端模式映射：前端 `source` 保存为后端 `markdown`，后端 `markdown` 加载为前端源码模式。
- `preview` 保持临时视图，不写入数据库。
- 迁移后用户主动选择源码、富文本或分栏时，选择可以正常保存并在下次打开时恢复。

## 回滚方式

1. 回滚前端大纲导航和编辑模式映射代码。
2. 执行 `alembic downgrade 0014_ai_optimization_provider` 只恢复数据库默认值；降级不会批量改写现有文章的编辑偏好。
3. 如确需把所有文章重新设为源码模式，应先备份并单独执行受控数据更新，不应与结构降级混在一起。
4. 重新执行现网部署。

## 遗留风险

- 富文本编辑器内部 DOM 由 Milkdown 维护，后续升级 Milkdown 时需要回归标题选择器。
- 极长文章采用平滑滚动，滚动完成时间取决于浏览器；定位目标不依赖固定延迟。
- 本次迁移将历史 `markdown` 值视为旧默认并统一改为富文本，这是一次性产品行为；迁移后新产生的源码偏好不会再被自动改写。
