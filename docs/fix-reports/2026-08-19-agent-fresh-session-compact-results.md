## 现象

进入“自助 Agent”页面时，前端会自动恢复最近的活跃会话并加载历史消息、历史计划和执行结果。长会话中，执行计划、执行记录和文本结果会同时展开，占用大量纵向空间，用户需要滚动较长距离才能开始新任务。

## 根因

- 页面挂载后先清空本地状态，随后立即调用历史加载接口，导致旧消息重新进入时间线。
- 首次发送消息时优先复用最近的活跃会话，而不是创建新的会话，因此页面即使暂时空白，后续轮询仍可能关联旧任务。
- 活跃执行计划默认展开；执行记录和结果正文没有统一的折叠容器，终态 Agent 状态也会继续保留在页面上。

## 修改

- 进入 Agent 页面时只初始化空白本地状态，不请求历史消息、历史计划或旧会话详情。
- 当前页面首次发送消息时创建全新会话；同一页面内的后续消息仍复用这个新会话，保证连续上下文。
- 移除“加载更早消息”入口，避免当前任务页面再次铺开历史聊天。
- 执行计划、执行记录、结果消息和结构化处理结果默认折叠，只显示状态、数量和短摘要；用户需要时可以手动展开。
- 已完成的 Agent 运行状态不再作为常驻卡片展示，运行中和等待确认状态仍保持可见。
- 为文本结果增加最大高度和内部滚动，防止展开后撑满页面。

## 遗留风险

- 历史会话仍保存在数据库中，只是不再由当前 Agent 页面自动展示；后续如果需要历史中心，应使用独立入口而不是恢复到任务页面。
- 刷新页面会开始新的空白会话视图，刷新前仍在后台运行的任务可以在全局任务中心查看，但不会自动恢复到新页面时间线。
- PWA 可能短暂保留旧静态资源；强制刷新或等待 Service Worker 更新后即可加载新界面。
- 当前结果摘要按字符数截断，复杂结构化结果仍需展开查看。
