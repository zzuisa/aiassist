# 修复复盘：Agent 过期失败与完整历史重复展示（2026-08-19）

- 分类：AI Assist 修复复盘
- 影响范围：自助 Agent 会话页的失败提示、历史消息加载和轮询行为

## 现象

用户每次打开同一个 Agent 会话都会看到多条内容相同的“处理消息时发生错误，消息已保留，可以安全重试”提示，同时页面一次加载较多历史消息。旧失败长期占据当前操作区，看起来像系统仍在持续报错。

## 根因

- 后端 `active_turns` 查询排除了成功和取消状态，却长期保留所有 `failed`、`stalled` 终态记录，历史失败因此永久返回。
- 前端对返回的每条失败记录分别渲染重试卡，并在 `active_turns` 非空时继续轮询，没有区分运行中状态与终态失败。
- 首次消息查询采用从最早记录开始的通用分页，默认最多返回 50 条；前端已有加载更多方法但没有可见入口，也没有“最近消息窗口”的后端查询语义。

## 修改

- `active_turns` 现在返回真实运行中的 Turn，并最多附带 1 条最近 24 小时内、尚未产生重试子项的失败或停滞记录。
- 前端再次限制失败提示最多显示最新 1 条，并且只有存在非终态 Turn 时才持续轮询。
- 新增最近消息窗口查询：打开会话只加载最近 12 条并保持时间正序。
- 增加“加载更早消息”按钮，用户主动请求时按游标向前加载另一页；实时轮询仍使用原有向后游标，不混淆分页方向。
- 所有历史消息和失败记录继续保存在数据库中，没有删除审计或重试依据。

## 验证

1. 全部会话相关后端测试 141 项通过；新增覆盖过期失败、重试链、最近窗口和向前分页。
2. 前端 Agent 组件测试 12 项通过；TypeScript、ESLint、Ruff 和 Git diff 检查通过。
3. Node 24 前端生产构建和 Compose 后端、前端镜像构建通过。
4. 后端、前端和 Nginx 热更新后均为 healthy。
5. 使用内部 API 对现有会话验证：`active_turns` 从 4 条历史失败降为 0；首次只返回 12 条消息并给出更早游标，随后成功加载下一页 12 条。
6. 线上前端构建产物包含“加载更早消息”入口。

## 日志检索方式

在 Kibana 的 `logs-aiassist-*` 和 `nginx-aiassist-*` 中按 Agent 会话路径、`turn_id` 或稳定错误码检索。服务端可使用：

```bash
./deploy/scripts/deploy.sh logs backend | rg '/agent/conversations|agent_message_cursor|ERROR|exception'
./deploy/scripts/deploy.sh logs worker-heavy | rg 'conversation_turn_execution_failed|turn_id'
./deploy/scripts/deploy.sh logs nginx | rg '/api/v1/agent/conversations'
```

日志分享前必须移除认证 Cookie、CSRF Token、用户消息正文和其他密钥。

## 遗留风险

- 失败提示 24 小时窗口和最近 12 条消息是当前产品默认值；后续如需用户可配置，应通过设置项扩展，不应直接增加首屏查询量。
- 终态失败退出提示区后仍保留在数据库，当前页面没有独立的历史失败审计筛选器。
- 旧客户端若同时传入实时游标与最近历史参数会收到稳定的游标冲突错误，需要升级到新的前端调用方式。
- 线上目前为热更新，源代码仍需按正式发布流程提交并纳入发布记录。
