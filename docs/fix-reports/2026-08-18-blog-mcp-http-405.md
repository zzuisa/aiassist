# 修复复盘：博客 MCP HTTP 连接 405（2026-08-18）

- 分类：AI Assist 修复复盘
- 影响范围：通过 MCPJam 等 Streamable HTTP 客户端访问 AI Assist 内部博客能力

## 现象

MCPJam 连接名为 `roguelife` 的服务器时，Streamable HTTP 的 `POST` 请求收到 Nginx 405 HTML 页面；客户端回退到 SSE 后又因响应类型不是 `text/event-stream` 而失败。客户端无法完成 MCP 初始化，也无法查看内部博客工具。

## 根因

配置中的地址指向普通 Web 页面入口。AI Assist 当时只具备调用外部 MCP Server 的客户端能力，没有对外提供博客 MCP 协议端点，因此请求被前端静态站点处理：静态入口不接受 `POST`，也不会返回 MCP 所需的 JSON 或事件流响应。

## 修改

- 新增基于官方 Python SDK 的无状态 Streamable HTTP MCP Server，公网端点为 `/api/v1/mcp/blog/mcp`。
- 暴露 `blog.list_posts`、`blog.get_post`、`blog.search_posts`、`blog.timeline`、`blog.list_categories` 和 `blog.list_tags` 六个只读工具；所有数据继续按令牌绑定用户隔离。
- 新增独立的 `blog:read` MCP Bearer Token。普通网页登录令牌不能调用 MCP，MCP 令牌也不能调用普通 REST API。
- 增加请求体大小、分页数量、搜索长度和分类数量上限，并启用 DNS rebinding 防护。
- 增加令牌签发 CLI、部署辅助命令、MCPJam 配置说明以及认证和协议契约测试。
- 沿用现有 `/api/` Nginx 反向代理规则，不再让 MCP 请求落到前端静态入口。

## 验证

1. Ruff、Shell 语法检查和 Git diff 检查通过。
2. 新增认证与 MCP 契约测试通过；认证、文章 API 相关回归共 23 项通过。
3. 公网端点在未携带 Bearer Token 时返回 JSON 401，不再返回 Nginx 405 HTML。
4. 使用官方 MCP 客户端经公网 Nginx 完成 Streamable HTTP 握手，发现上述六个工具。
5. 使用短期探测令牌成功调用 `blog.list_posts`，返回非错误结果；探测过程中未输出或持久化令牌。

## 日志检索方式

在 Kibana 的 `logs-aiassist-*` 与 `nginx-aiassist-*` 索引中按路径 `/api/v1/mcp/blog/mcp` 检索，并结合 HTTP 状态码筛选 `401`、`405` 或 `5xx`。服务端可使用：

```bash
./deploy/scripts/deploy.sh logs backend | rg 'blog_mcp|/api/v1/mcp/blog/mcp|ERROR|exception'
./deploy/scripts/deploy.sh logs nginx | rg '/api/v1/mcp/blog/mcp'
```

检索和分享日志时必须移除 `Authorization` 请求头及任何令牌内容。

## 遗留风险

- 当前仅开放读取能力；创建、修改、删除和发布文章仍应使用现有受 CSRF 与确认机制保护的产品流程。
- MCP Token 在有效期内等同于对应用户的博客读取权限，需由用户在本机密码管理器或 MCPJam 的安全配置中保存；首版尚未提供单枚令牌主动吊销列表。
- 客户端若仍配置站点根地址，仍会收到非 MCP 响应；必须使用完整的 MCP 协议路径。
- 线上后端目前已热更新并完成验证，源代码仍需按项目发布流程提交和纳入下一次正式发布记录。
