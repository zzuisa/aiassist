# Feature Specification: 博客 Agent 内容管理

**Feature Branch**: `006-agent-content-management`

**Created**: 2026-08-04

**Status**: Draft

**Input**: User description: "将博客优化涉及的所有 Agent、Prompt 与 Skill 统一纳入博客管理，允许安全更新文案，并按照 Agent 实际执行结构直观展示其位置、顺序和依赖关系。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 看懂完整执行结构 (Priority: P1)

作为博客维护者，我可以在博客管理中看到一次 AI 优化从输入、总控诊断、专业 Agent、能力/Skill、质量校验到候选保存的完整结构，并能从每个节点查看它的职责、状态、输入输出和上下游关系。

**Why this priority**: 当前 Agent、Prompt 和能力分散在代码、环境配置与 Skill 页面中。先建立一张与真实运行一致的地图，用户才能知道应修改什么以及修改会影响哪里。

**Independent Test**: 打开“Agent 编排”页面，不进行任何编辑，即可沿执行方向识别总控、Editor、Logic、Data、Scene、Illustration、质量校验、候选保存及其关联 Skill/能力，并区分必经、条件执行和不可用节点。

**Acceptance Scenarios**:

1. **Given** 当前博客优化能力已加载，**When** 用户打开 Agent 编排页面，**Then** 系统按实际执行方向显示所有已知节点、连接关系和执行条件，而不是按名称简单罗列。
2. **Given** 某专业 Agent 只在价值门控通过时执行，**When** 用户查看该节点，**Then** 页面明确标记其为条件节点并说明门控、预算和能力依赖。
3. **Given** 某能力未注册、停用或不可用，**When** 用户查看执行结构，**Then** 节点仍保留在正确位置并显示不可用原因，不伪装成已执行能力。
4. **Given** 用户在窄屏设备打开页面，**When** 浏览执行结构，**Then** 可用分阶段纵向结构完整阅读，不依赖横向拖动画布才能理解流程。

---

### User Story 2 - 安全修改 Agent 文案与 Prompt (Priority: P1)

作为博客维护者，我可以从执行结构中的 Agent 节点进入编辑，调整名称、说明和可编辑指令文案；每次保存形成不可变版本，经过校验并显式启用后才影响新任务，运行中与历史任务继续使用提交时固定的版本。

**Why this priority**: 用户提出的核心价值是能够试改文案。版本、预览和显式启用可以让试验可回退，并避免一次错误编辑破坏线上优化链路。

**Independent Test**: 修改 Editor Agent 的可编辑指令并保存为新草稿版本，验证旧版本仍为生效版本；通过校验并启用后，新任务绑定新版本，旧任务仍展示旧版本。

**Acceptance Scenarios**:

1. **Given** Agent 已有生效版本，**When** 用户修改可编辑文案并保存，**Then** 系统创建新版本且不改写历史版本，也不自动影响已提交任务。
2. **Given** 新版本包含空必填段、超限内容、未知占位符或试图覆盖锁定安全规则，**When** 用户校验或启用，**Then** 系统阻止启用并给出字段级、可操作的错误。
3. **Given** 新版本校验通过，**When** 用户查看生效影响并确认启用，**Then** 只有之后提交的新任务使用该版本。
4. **Given** 用户发现新文案效果不佳，**When** 用户恢复历史版本，**Then** 系统复制历史内容生成新的当前版本，历史链保持不变。
5. **Given** 系统安全约束、输出契约或受保护事实规则属于锁定内容，**When** 用户编辑 Agent，**Then** 页面允许查看其作用但不能删除、放宽或用自由文本覆盖。

### User Story 3 - 在 Agent 位置管理关联 Skill 与能力 (Priority: P2)

作为博客维护者，我可以在每个 Agent 节点看到它调用或依赖的文章 Skill、可视化/图表/图片能力及当前可用状态，并从该位置进入已有 Skill 管理或处理缺失配置。

**Why this priority**: Agent 决策和 Skill/能力执行是不同层次。把关联项放回实际调用位置，可减少“看见 Skill 但不知道谁在何时使用”的困惑，同时复用已有 Skill 版本管理。

**Independent Test**: 从 Logic Agent 节点查看其 `visualize` 能力与适用文章 Skill，进入现有 Skill 编辑页后返回，执行图仍保持定位；停用能力时图上显示降级结果。

**Acceptance Scenarios**:

1. **Given** Agent 关联一个或多个 Skill/能力，**When** 用户展开节点，**Then** 系统区分“内容规范 Skill”和“执行能力”，显示来源、状态、版本和作用。
2. **Given** 内容规范 Skill 已由现有博客 Skill 页面管理，**When** 用户从执行图打开它，**Then** 系统复用同一身份与版本记录，不创建重复副本。
3. **Given** 能力由部署配置提供且含敏感连接信息，**When** 用户查看能力，**Then** 页面只显示安全清单字段与可用性，不显示地址中的凭据、令牌、Cookie、私钥或密钥文件内容。
4. **Given** Agent 的必需能力不可用，**When** 用户准备启用相关 Agent 版本，**Then** 系统说明会跳过还是阻止执行，并提供配置入口或运维提示。

### User Story 4 - 预览变更并验证实际绑定 (Priority: P2)

作为博客维护者，我可以用临时样例预览某个 Agent 版本的组合指令、计划选择和预期影响，而不修改正式文章；任务完成后，我也能追溯实际使用的总控、Agent、Prompt 与 Skill 版本。

**Why this priority**: 单独编辑文本不能证明它在真实编排中的效果。无副作用预览和运行追溯是安全试验与问题定位的必要闭环。

**Independent Test**: 对一个未启用的 Logic Agent 草稿版本运行样例预览，验证不产生文章修订；再提交正式优化任务，任务详情能列出固定的编排版本、已选/跳过 Agent、Prompt 版本和 Skill 版本。

**Acceptance Scenarios**:

1. **Given** 用户选择一个 Agent 草稿版本和临时样例，**When** 发起预览，**Then** 系统展示该版本在完整执行链中的位置、门控结果和安全的组合指令摘要，不创建或修改正式文章。
2. **Given** 预览依赖模型或能力暂时失败，**When** 任务结束，**Then** 草稿版本和样例仍可编辑重试，失败不改变当前生效版本。
3. **Given** 正式博客优化任务已提交，**When** 用户查看任务详情，**Then** 可回答“用了哪个总控版本、选择或跳过了哪些 Agent、各自使用哪个 Prompt/Skill 版本以及为什么”。
4. **Given** Agent 配置在任务运行期间被修改或停用，**When** 原任务继续执行，**Then** 原任务仍按提交时快照执行，新配置只影响新任务。

### User Story 5 - 管理变更影响与审计 (Priority: P3)

作为博客维护者，我可以比较版本、查看变更摘要、启停影响和操作历史，并在不确定时恢复系统默认文案，从而长期维护 Agent 内容而不失去可追溯性。

**Why this priority**: 当可编辑对象增多后，需要治理能力来避免配置漂移，但它可以在核心查看、编辑与绑定闭环之后交付。

**Independent Test**: 比较同一 Agent 的两个版本，查看字段级差异与受影响的新任务范围；恢复系统默认后生成新版本并留下活动记录。

**Acceptance Scenarios**:

1. **Given** Agent 存在多个版本，**When** 用户比较版本，**Then** 系统突出显示名称、说明、指令段、参数和依赖的变化。
2. **Given** 用户准备停用条件 Agent 或启用新版本，**When** 查看影响摘要，**Then** 系统说明受影响的执行分支、内容类型、默认 Skill 和新任务范围。
3. **Given** 用户选择恢复系统默认，**When** 确认操作，**Then** 系统以当前内置默认生成一个新的用户版本并记录来源，不删除用户历史。
4. **Given** 配置被创建、校验、启用、停用或恢复，**When** 用户查看活动记录，**Then** 能看到操作者、对象、版本、时间和安全变更摘要，不包含完整私密 Prompt 或密钥。

### Edge Cases

- 内置代码新增、删除或重命名 Agent 时，已有用户覆盖如何映射，页面如何标记已弃用或等待迁移的版本。
- 用户同时在两个页面编辑同一 Agent 时，后保存者必须收到版本冲突，不能静默覆盖。
- 当前生效版本被历史任务引用时，停用或恢复不得修改任务快照。
- Agent Prompt 引用文章标题、正文、共享诊断等变量时，只允许受支持的占位符；未知变量不得在运行时静默变为空。
- Prompt 或说明中包含类似密钥的内容时，系统应阻止保存或要求移除，日志和活动记录只保留摘要与哈希。
- 能力清单读取失败时，执行图仍展示已知结构并将实时状态标为未知，不能导致整个博客管理不可用。
- 执行图节点很多或名称很长时，桌面与移动端都必须保持可读、可键盘访问，并提供列表式替代视图。
- 某 Agent 无独立可编辑 Prompt、仅执行确定性校验时，应显示为锁定系统节点，而不是伪造可编辑文本。
- 草稿版本长期未启用时不影响生产执行；用户可删除未被引用的草稿，但生效或被引用版本按审计策略保留。
- 旧任务没有编排版本快照时，应明确标记为“旧版记录不完整”，不得猜测或套用当前版本。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在博客管理中提供统一的 Agent 编排入口，覆盖博客 AI 优化实际涉及的总控、专业 Agent、确定性校验节点、内容规范 Skill、执行能力和候选保存阶段。
- **FR-002**: 系统 MUST 按真实执行方向、阶段、条件分支和依赖展示节点；视觉位置不得暗示不存在的调用关系。
- **FR-003**: 每个节点 MUST 显示稳定标识、用户可读名称、职责、节点类型、执行模式、状态、输入输出摘要、上游、下游及跳过/阻止条件。
- **FR-004**: 系统 MUST 区分必经节点、条件 Agent、内容规范 Skill、外部或本地执行能力、锁定系统校验和持久化阶段。
- **FR-005**: 执行结构 MUST 提供适用于窄屏和辅助技术的分阶段列表视图；图形连线不得成为理解关系的唯一方式。
- **FR-006**: 用户 MUST 能从 Agent 节点查看当前生效版本、草稿版本、历史版本、关联 Skill/能力及近期运行摘要。
- **FR-007**: 用户 MUST 能编辑 Agent 的显示名称、说明和明确标记为可编辑的业务指令段；系统安全规则、所有权规则、输出契约和事实保护规则 MUST 保持锁定。
- **FR-008**: 每次保存 Agent 配置 MUST 创建不可变的新版本，包含版本号、基础内置版本、变更说明、创建者和创建时间，不得原地改写历史版本。
- **FR-009**: 保存新版本与启用新版本 MUST 是两个独立动作；草稿保存不得改变生产任务使用的版本。
- **FR-010**: 启用前系统 MUST 校验必填段、长度、允许占位符、参数范围、依赖、输出兼容性和锁定安全边界，并返回字段级错误与警告。
- **FR-011**: 启用新版本 MUST 展示影响摘要并要求显式确认；影响范围只针对之后提交的新任务。
- **FR-012**: 恢复历史版本或系统默认 MUST 复制目标内容形成新版本，不得移动、删除或改写历史记录。
- **FR-013**: 系统 MUST 使用乐观并发控制保护 Agent 编辑和启用，冲突时保留双方内容并要求用户重新比较。
- **FR-014**: 正式任务提交时 MUST 固定总控配置版本、所有可被选择的 Agent 版本、实际选择/跳过结果、内容规范 Skill 版本、能力清单摘要和安全策略版本。
- **FR-015**: 运行中任务 MUST 不受后续 Agent 编辑、启停、能力状态刷新或默认 Skill 变化影响。
- **FR-016**: 任务详情 MUST 展示实际编排快照，包括总控版本、Agent 选择/跳过理由、Prompt 版本、Skill 版本、能力结果和质量校验结果。
- **FR-017**: 系统 MUST 复用现有博客 Skill 身份、不可变版本、默认匹配和测试能力；统一页面不得复制或分叉同一 Skill 的业务真相。
- **FR-018**: 系统 MUST 在 Agent 节点区分内容规范 Skill 与执行能力，并显示它们在执行链中的不同职责。
- **FR-019**: 能力清单 MUST 只暴露名称、类型、安全说明、启用状态、健康状态和配置来源等非敏感字段；端点凭据、令牌、Cookie、私钥、密钥内容和原始私密响应不得通过页面、接口、日志或活动记录暴露。
- **FR-020**: 能力缺失或停用时，系统 MUST 按真实策略显示“跳过、降级或阻止”，不得伪造调用结果或把未知状态显示为成功。
- **FR-021**: 用户 MUST 能用临时文本或显式选择的样例文章预览草稿/历史 Agent 版本；预览不得修改正式文章、当前 Agent 版本或正式候选。
- **FR-022**: 预览 MUST 经过与正式任务一致的结构校验和安全边界，并显示执行计划、门控结果、组合内容摘要、验证结果、成本/数量上限及可操作错误。
- **FR-023**: 系统 MUST 对 Agent 配置的创建、保存、校验、启用、停用、恢复和删除草稿记录活动；活动仅保存安全元数据、变更摘要和必要业务 ID。
- **FR-024**: 用户 MUST 能比较任意两个可访问版本的字段级差异，并识别当前生效、草稿、历史、内置默认和已弃用状态。
- **FR-025**: 当内置 Agent 清单或默认 Prompt 升级时，系统 MUST 保留用户版本，标记基础版本漂移，并在启用前提示重新校验，不得静默覆盖。
- **FR-026**: 系统 MUST 为旧任务与旧用户配置提供明确兼容状态；缺少历史快照时显示记录不完整，不得根据当前配置反推历史。
- **FR-027**: Agent、Prompt、Skill、预览和运行快照的所有读取与写入 MUST 按当前所有者过滤，默认仅内部可见。
- **FR-028**: Agent 管理接口 MUST 使用稳定、版本化的输入输出契约；未知写入字段、未知节点标识和未知占位符必须被拒绝。
- **FR-029**: 系统 MUST 在结构化日志中记录 trace、用户、Agent、版本和任务等安全标识及错误代码，不得记录文章正文、完整 Prompt、模型原始响应或任何密钥。
- **FR-030**: 页面 MUST 支持按节点类型、状态、能力可用性和名称筛选，并可从详情返回原执行位置。
- **FR-031**: MVP MUST 保持执行拓扑由系统定义；用户可管理内容版本和允许的启停项，但不得通过拖拽任意改变运行顺序、绕过质量校验或把条件节点改成必经节点。
- **FR-032**: 系统 MUST 为不可编辑的确定性阶段显示只读原因，使“全部纳入管理”不被误解为“全部都能修改”。

### Key Entities *(include if feature involves data)*

- **Agent Definition**: 博客执行链中的稳定节点身份，描述节点类型、系统职责、执行阶段、是否条件执行、可编辑范围和内置默认版本。
- **Agent Version**: 某 Agent 的不可变用户配置快照，包含显示文案、可编辑指令段、受支持参数、基础内置版本、校验状态、变更摘要和创建信息。
- **Agent Activation**: 当前用户对某 Agent 的生效版本与允许启停状态；保存草稿与生产启用相互独立。
- **Execution Topology**: 系统定义的执行阶段、节点、边和条件说明，用于展示和验证，不允许用户绕过固定安全阶段。
- **Capability Descriptor**: Agent 可调用的本地函数、受控外部接口或其他注册能力的安全清单，只包含非敏感身份、类型、状态与用途。
- **Blog Skill / Skill Version**: 既有文章处理规范及其不可变版本，在统一编排视图中被引用而不复制。
- **Orchestration Snapshot**: 正式任务提交时固定的总控、Agent、Prompt、Skill、能力和策略版本及选择/跳过理由。
- **Agent Preview Run**: 使用临时样例验证指定配置版本的隔离运行记录，不产生正式文章版本或候选。
- **Agent Activity**: 配置与启用相关操作的安全审计摘要。

### Data Safety & AI Control *(mandatory when the feature stores content or uses AI)*

- **Durable acceptance point**: Agent 文案在新不可变版本、所有者、基础版本与校验状态同一事务保存成功后才视为已保存；只有激活记录更新成功后才视为对新任务生效。正式任务在编排快照与任务记录同一事务持久化后才可派发。
- **AI authority boundary**: AI 可对临时样例生成预览和候选，但不得自动启用 Agent 版本、改写锁定安全规则、改变系统拓扑、公开文章或直接覆盖正式文章。启用、恢复和候选应用均需遵循明确的人类操作与现有审核边界。
- **Failure fallback**: Agent 管理、能力健康检查、模型或队列失败时，已有生效版本与正式文章保持可用；草稿不会影响生产，预览可重试，能力失败按既定跳过/降级/阻止策略显示。
- **Privacy and ownership**: Agent 配置、Prompt、Skill、样例、快照与活动默认继承博客内部私有和所有权规则。接口、日志、通知和导出均不得包含密钥或不必要的文章正文与完整 Prompt。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户首次打开页面后，在 3 分钟内能正确指出总控、至少五类专业 Agent、关联 Skill/能力、质量校验与候选保存的先后和条件关系。
- **SC-002**: 100% 的 Agent 文案保存操作产生新版本；0 个已提交任务因后续编辑而改变其绑定版本。
- **SC-003**: 100% 的新正式优化任务可追溯到总控版本、实际选择/跳过的 Agent、Prompt 版本、Skill 版本及能力结果或明确缺失原因。
- **SC-004**: 用户可在 5 分钟内完成“定位 Agent → 修改文案 → 校验 → 预览 → 启用或放弃”的完整流程，且不修改任何正式文章。
- **SC-005**: 所有未知占位符、越权安全改写、超限 Prompt 和不兼容输出在启用前被拦截；无无效配置进入新任务。
- **SC-006**: 能力未注册、停用或检查失败时，100% 在执行图和预览结果中显示真实的跳过、降级、阻止或未知状态，不出现伪造成功。
- **SC-007**: 在 360px 宽度、键盘和屏幕阅读器路径下，用户无需依赖图形连线即可访问全部节点、关系和编辑入口。
- **SC-008**: Agent 编排页面在正常个人服务器数据规模下 95% 首屏加载时间少于 2 秒，配置保存反馈 95% 少于 2 秒；异步预览状态变化 95% 在 5 秒内可见。
- **SC-009**: 安全测试中，页面、接口、日志、活动记录和任务摘要泄露的密码、令牌、Cookie、私钥或密钥内容数量为 0。
- **SC-010**: 内置 Agent 默认升级后，100% 的用户覆盖保持可恢复且被明确标记为已校验、需重验或已弃用，不发生静默覆盖。

## Assumptions

- 本功能是 `005-blog-content-management` 的增量扩展，复用现有博客认证、所有权、Skill、任务、候选、活动记录、LLM 网关和任务中心。
- “所有 Agent”指当前博客内容增强执行链及以后通过系统清单注册的博客 Agent，不扩展为总站所有模块的通用 Agent/Prompt 平台。
- “按照执行结构放置”默认指系统根据真实拓扑自动布局和分阶段展示；MVP 不允许用户拖拽改变生产执行顺序。
- MVP 首批覆盖总控编排器、Editor、Logic、Data、Scene Image、Illustration、质量校验和候选保存；无独立 Prompt 的确定性节点以只读方式纳入。
- 用户可编辑业务说明和 Agent 指令层，系统级安全底座、输出契约、所有权与事实保护保持锁定，并在最终组合时始终优先。
- 现有博客 Skill 继续是内容规范的唯一业务真相；可视化、图表、图片检索和图片生成等注册能力作为另一类依赖展示。
- 单个个人账户通常只有少量 Agent 与数十个 Skill，但历史版本和任务快照长期保留；列表与比较需要分页或有界加载。
- 用户未要求公开发布 Agent 配置、Prompt 或预览结果；所有内容默认保留为 AI Assist 内部数据。
