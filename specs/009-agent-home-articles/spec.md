# Feature Specification: Agent 首屏与文章结果交互

**Feature Branch**: `009-agent-home-articles`  
**Created**: 2026-08-13  
**Status**: Draft  
**Input**: User description: "优化自助 Agent 首屏，不自动展示历史对话；将文章查询结果以可交互卡片展示并支持打开查看。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从清爽的 Agent 首屏开始 (Priority: P1)

作为用户，我打开自助 Agent 时希望直接看到简洁的欢迎和输入区，而不是以前会话的聊天记录，以便专注发起新的请求。

**Why this priority**: 历史记录占据首屏会阻碍用户开始新任务，是当前最直接的体验问题。

**Independent Test**: 打开 Agent 页面，验证页面不请求或渲染任意既有会话消息，并能直接输入和发送新请求。

**Acceptance Scenarios**:

1. **Given** 用户拥有任意数量的历史会话，**When** 打开 Agent 页面，**Then** 首屏不显示任何历史消息、失败记录或历史任务状态。
2. **Given** 用户位于空白首屏，**When** 发送第一条消息，**Then** 页面创建或开始一个新会话，并只显示本次会话产生的内容。
3. **Given** 用户刷新尚未发送消息的 Agent 页面，**When** 页面重新加载，**Then** 仍保持清爽首屏且不恢复旧聊天记录。

---

### User Story 2 - 以可操作卡片浏览文章查询结果 (Priority: P1)

作为用户，当 Agent 查询到文章时，我希望在对话结果中看到清晰的文章卡片，并能点击打开对应文章查看，而无需复制 ID 或重新搜索。

**Why this priority**: 查询结果是 Agent 的核心产出；可直接打开文章能把对话结果转化为下一步行动。

**Independent Test**: 发起返回多篇文章的查询，验证每篇文章均显示独立卡片，点击后进入该文章的详情页面。

**Acceptance Scenarios**:

1. **Given** 查询返回一篇或多篇用户有权访问的文章，**When** Agent 显示结果，**Then** 每篇文章显示独立且可点击的卡片，至少包含标题和可用的分类、标签或摘要信息。
2. **Given** 用户点击文章卡片，**When** 导航完成，**Then** 打开该用户有权查看的文章详情，而不是通用列表或无效链接。
3. **Given** 查询结果缺少可展示的某些元数据，**When** 渲染文章卡片，**Then** 卡片仍可打开文章，且不显示空白或技术字段。

---

### User Story 3 - 在单次会话中持续工作 (Priority: P2)

作为用户，我希望在发起新请求后继续看到本次会话的后续消息和文章卡片，以便基于结果继续提问或查看文章。

**Why this priority**: 隐藏历史不应破坏当前工作上下文。

**Independent Test**: 在同一页面连续发送两条消息，验证它们和相应结果按时间显示，且刷新前不会混入旧会话。

**Acceptance Scenarios**:

1. **Given** 用户已在本页发送消息，**When** 新的回复或文章结果到达，**Then** 它仅追加至当前页面会话。
2. **Given** 当前会话的文章结果显示为卡片，**When** 用户继续提问，**Then** 已显示的卡片与对话上下文保持可见。

### Edge Cases

- 查询没有匹配文章时，结果应明确说明无匹配项，且不显示空卡片区域。
- 返回的文章链接不可用或文章已被删除时，卡片应保持安全的不可用提示，不能跳转至他人内容。
- 消息发送或结果加载失败时，首屏仍保持可输入状态，并显示可理解的重试提示。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须在用户首次打开 Agent 页面时显示欢迎和输入区，且不得自动加载或展示该用户的任意历史会话消息。
- **FR-002**: 系统必须在用户发送首条消息后创建一个新的当前会话，并只在该页面会话中展示后续消息、状态和结果。
- **FR-003**: 系统必须保留既有会话记录的持久化和所有权边界，但首屏不得把它们作为默认内容恢复。
- **FR-004**: 系统必须将文章查询结果在关联的对话结果中呈现为逐篇独立、可点击的文章卡片。
- **FR-005**: 每张文章卡片必须使用该用户有权访问的文章标识打开文章详情，并在可用时显示标题以及非敏感元数据。
- **FR-006**: 系统必须在没有文章结果、结果不完整或文章不可用时提供清晰反馈，不展示空白、原始 JSON 或内部标识。
- **FR-007**: 系统必须使当前会话中的文章结果在后续提问期间保持可访问，直到用户离开或刷新页面。
- **FR-008**: 系统必须继续保持写入确认、消息持久化、会话所有权和现有失败重试行为不变。

### Key Entities *(include if feature involves data)*

- **当前页面会话**: 用户在本次访问期间主动发起的对话及其消息、状态和结果。
- **文章结果卡片**: 一篇受当前用户访问控制保护的文章查询结果，包含展示信息和进入详情的动作。
- **历史会话**: 已持久化但不在 Agent 首屏自动展示的先前对话。

### Data Safety & AI Control *(mandatory when the feature stores content or uses AI)*

- **Durable acceptance point**: 用户发送消息后，消息与所属会话按既有规则持久化；仅页面初始展示策略改变。
- **AI authority boundary**: Agent 只能返回用户已授权查看的文章；文章卡片不授予额外权限，写入仍须明确确认。
- **Failure fallback**: 加载或查询失败时，用户仍能发起新请求、查看可见提示并重试，不显示内部错误详情。
- **Privacy and ownership**: 文章卡片及其链接必须仅代表当前用户可访问的文章；历史会话继续仅对其所有者可见。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在拥有至少 100 条历史消息的账户中，100% 的 Agent 首次打开不显示历史消息或历史失败状态。
- **SC-002**: 用户在首屏输入并发送第一条消息的流程不超过 2 个交互步骤。
- **SC-003**: 对返回文章的查询，100% 的有效文章结果均能从卡片在一次点击内打开对应详情。
- **SC-004**: 在窄屏和桌面视图中，文章卡片标题与打开动作均清晰可用，且不展示内部 ID 或原始结果数据。

## Assumptions

- 现有文章详情页和用户访问控制可被复用。
- “重新打开 Agent”默认表示新会话开始；历史会话浏览不属于本次首屏功能范围。
- 首版文章卡片展示标题、分类、标签和已有的安全摘要字段；不新增文章编辑或批量操作。
